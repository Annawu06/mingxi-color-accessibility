# 色彩处理边界

明晰的四个模式是用户可自行比较的视觉调整预设，不是色觉缺陷模拟，也不是经临床验证的 daltonization 算法。模式名称表示设计目标，不表示对用户色觉类型的判断。

页面整体和单独增强的图片、视频、Canvas 使用同一组 CSS `filter` 预设与强度参数。同一元素只应用一层预设滤镜。非颜色提示（状态符号、链接下划线、图表纹理）独立于滤镜。Canvas 图表提示读取 Chart.js 提供的结构化数据，并在图表绘制后叠加纹理；不分析 Canvas 像素。

文字对比度使用 WCAG 2.1 的相对亮度和对比度公式。透明纯色背景按 Alpha 合成；背景图片、渐变、混合模式和透明元素会标记为无法可靠判断，不自动修正。

## 图表与状态提示的支持范围

| 网页内容 | 当前处理方式 | 测试时应关注 |
| --- | --- | --- |
| 网页内联 SVG 图表 | 识别带 `role="img"` 或 `aria-label` 包含 `chart`、`图表` 的 `<svg>`。图形需带 `data-series`、`data-series-id`，或位于带这些属性、`aria-label` 包含 `series`、`系列` 的 `<g>` 中，且至少有两个系列。符合条件的 `rect`、`path`、`circle`、`polyline`、`polygon` 可获得纹理或线型；带数值 `data-value` 的柱形 `rect` 可增加数值标签。 | 有明确系列标记的多系列图；无系列标记的图应保持原状。新增节点和属性变化会触发重新增强；复杂图表仍需实站验证。ECharts、Highcharts 的 DOM 图表只有满足相同标记条件才会增强。 |
| 图片中的图表，包括通过 `<img>` 加载的 SVG | 可通过颜色滤镜调整显示。 | 不识别系列、坐标或数值，不添加图表纹理和标签。 |
| Chart.js Canvas 柱形图或折线图 | 页面将 Chart.js 暴露为 `window.Chart`，且至少有两个可见的柱形或折线数据集时，读取数据集名称、坐标轴标题、坐标标签和数值，在 Canvas 后提供可展开数据表。柱形叠加不同方向的斜线纹理；折线叠加不同虚线。 | 测试两系列柱形图、折线图、数据更新、图例隐藏系列，以及关闭增强后纹理和数据表的恢复。数据表最多显示前 300 个点。 |
| 其他 Canvas 图表 | 可通过颜色滤镜调整显示。 | Canvas 像素没有通用的数据语义；未暴露 Chart.js 实例的页面，以及饼图等其他类型，暂不识别系列、坐标或数值，也不叠加纹理。 |
| 普通 DOM 状态元素 | 优先读取 `data-status`、`aria-invalid`，其次读取语义类名和 ARIA 标签。缺少状态文字时显示“✓ 成功”“! 警告”“× 错误”；原文已有状态词时只补符号。无法判断类型的 `role="alert"` 显示“i 提示”。表单控件的提示插入在控件后。 | 检查新增节点、类名与 `aria-invalid` 变化后提示是否更新；普通 `.error` 类不直接判为错误。没有语义标记的纯颜色状态仍无法自动判断。 |

图片、Canvas 和视频的单独滤镜由“增强图片、图表和视频”控制；页面颜色重映射开启时，它们随页面一起使用同一预设。内联 SVG 与 Chart.js Canvas 的纹理、线型和数据表由图表提示设置控制。悬浮提示中可计算的纯色背景文字按 WCAG AAA 阈值尝试调整；复杂背景和前景颜色组合仍需人工检查。CSS 生成的状态文字是视觉辅助，不替代网页自身的可访问名称或屏幕阅读器提示。

SVG 纹理线条会按系列填充色选用黑色或白色；无法可靠解析的填充色默认使用黑色。关闭增强时，只在原线型仍是插件设置的值时恢复，避免覆盖页面运行期间自行更新的线型。

弹窗的“诊断当前页面”会显示 SVG 候选及已增强数量、Canvas 总数及已增强数量、状态候选及已提示数量。导出的 JSON 还列出最多 50 个未识别 Canvas 的 DOM 位置与可访问标签，便于测试人员提供页面截图和复现步骤；报告不包含图像像素或图表数据。

要证明预设能提升辨识准确率，需要标准色卡和真实色觉差异用户实验；现有测试只验证计算、设置和页面恢复行为。
